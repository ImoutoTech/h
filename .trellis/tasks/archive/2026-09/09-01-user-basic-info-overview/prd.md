# 丰富用户基本信息概览

## Goal

把 Safe House 用户“基本信息”Tab 从四项静态资料扩展为可信、分层的账号与子应用概览，使普通用户能够判断账号安全状态，使拥有子应用权限的用户能够快速了解接入规模、近 30 天 OIDC 使用情况和最近账号活动。

## Background

- 当前 Tab 仅显示邮箱、用户 ID、加入时间、上次编辑以及编辑/退出操作；页头已展示头像、昵称、用户 ID 和角色。证据见 `safe-house/src/views/user/pages/user-info.vue:14-45` 和 `safe-house/src/views/user/view-index.vue:42-57`。
- 当前用户投影已经包含 `emailVerified` 与 `hasPassword`，并已有外部身份列表和当前用户子应用列表接口。
- `SubAppMeta.visitNum` 只在旧 `POST /app/:id` 回调中累加；标准 OIDC 流程不会更新该值，不能作为“子应用登录次数”。
- OIDC 授权结果、真实登录成功和最近活动当前没有可查询的持久化事件模型。
- 详细数据盘点与源码证据见 `docs/research/user-basic-info-metrics.md`。

## In Scope

- **P0 页面丰富**：使用现有账号、外部身份和子应用数据完成账号安全与子应用概览。
- **P1 核心事件与接口**：新增结构化登录、OIDC 授权/登录和账号行为事件，提供当前用户限定的 overview 与 activity API，并展示近 30 天指标和最近活动。
- 父任务包含两个可独立验收的子任务：
  - `09-01-user-overview-events-api`：后端事件模型、采集、聚合、保留和分页接口。
  - `09-01-user-basic-info-ui`：前端概览布局、数据接入、状态和响应式体验；依赖后端接口契约先完成。

## Requirements

### R1. 信息架构与权限

- 基本信息 Tab 分为账号资料/安全状态、子应用指标和最近活动三个层级。
- 页头已有的头像、昵称、用户 ID 和角色不在指标卡中重复。
- 子应用指标按现有“查看子应用”权限显示；无权限时隐藏开发者区域，有权限但无子应用时显示引导型空状态，不展示一排无意义的 `0`。

### R2. 指标真实性

- 子应用数量按当前用户作为 owner 的未删除子应用统计。
- OIDC 授权决策区分同意和拒绝；“授权次数”不能与模板授权或旧访问量混用。
- 子应用登录次数仅在 Authorization Code 成功兑换 token 时计数；授权码签发后未兑换不计入登录。
- `visitNum` 不作为本页面的登录或授权指标。
- 所有指标标明近 30 天等时间窗口；尚未采集或不适用的数据使用 `null` / 隐藏 / “暂未统计”语义，不得伪装成 `0`。

### R3. 账号与子应用概览

- 展示邮箱验证、密码设置、账号加入时间、资料更新时间和已绑定登录方式。
- 对有权限用户展示子应用总数、运行/关闭/封禁分布、近 30 天成功登录数、授权同意数和拒绝数。
- 账号安全状态使用状态列表或 Badge；业务数值使用与现有 Origin UI Vue/Tailwind 组件层一致的 Statistic Card。

### R4. 结构化活动

- 采集账号登录成功/失败、OIDC 授权同意/拒绝、OIDC 登录成功、资料/邮箱/密码变更、外部身份绑定/解绑、子应用与密钥重要操作。
- 最近活动只展示当前账号自己的操作与安全事件，不把其子应用全部终端用户流量混入个人时间线。
- 原始事件默认保留 90 天且保留期可配置；页面默认请求最近 20 条，API 支持分页。
- 事件元数据采用白名单，禁止持久化或返回密码、密码哈希、JWT、OAuth code/token、完整密钥、原始 Redis payload 和完整 IP。

### R5. 数据边界与体验

- 浏览器不拉取全量子应用或事件后自行聚合；overview 由后端一次返回页面所需快照，activity 独立分页。
- 新增请求有 loading、失败、空数据和重试状态。
- 桌面端与移动端保持清晰阅读顺序、语义化标题、键盘可达和非颜色唯一表达。

## Acceptance Criteria

- [ ] 基本信息 Tab 在桌面端和移动端形成清晰的账号、安全、子应用和活动层级，且不重复页头信息。
- [ ] 邮箱验证、密码状态、绑定登录方式、账号时间、子应用数量与状态分布均来自真实服务端数据。
- [ ] OIDC 登录数只统计成功 token exchange；授权同意/拒绝单独统计，并有自动化测试防止口径回退。
- [ ] 无子应用权限时不返回或展示开发者指标；有权限但无子应用时展示明确空状态。
- [ ] 页面不展示 `visitNum` 作为 OIDC 指标，也不把尚未采集/不适用渲染为 `0`。
- [ ] 最近活动可分页，默认展示最近 20 条；原始事件默认 90 天后清理，配置可覆盖默认值。
- [ ] 事件响应和日志中不出现密码、JWT、OAuth code/token、完整密钥或完整 IP。
- [ ] 后端 lint/build/test 与前端 test/type-check/lint/build 全部通过，并完成 768px 移动布局与键盘/错误状态人工检查。

## Out of Scope

- 解析 HLogger 文本或 Redis OIDC 临时记录来回填历史数据。
- P2 的 90 天趋势、日汇总表、Top 子应用、独立用户、通知运营分析和长期环比。
- 设备位置、完整 IP、风险评分、活跃会话列表和会话撤销。
- 重构现有“子应用”“登录方式”“管理”Tab 的完整功能。

## Key Decisions

- 实施范围为 P0 + P1，P2 另行迭代。
- 登录成功以 Authorization Code 成功兑换 token 为唯一计数点。
- 原始活动事件默认保留 90 天，页面指标窗口为近 30 天，最近活动默认 20 条。
- 页面同时服务普通用户和子应用 owner，开发者区域按权限与数据自适应。
