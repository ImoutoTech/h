# 优化邮件验证 HTML 模板样式

## Goal

为账号邮箱验证码补充清晰、可信且适合事务邮件阅读场景的 HTML 模板，让用户能快速识别验证码、用途与有效期，并保留纯文本降级内容。

## Background

- `account.email.verify` 由 `1787100000000-SsoEmailVerification.ts` 初始化，目前 `html` 为 `NULL`，主题和纯文本正文分别为“邮箱验证码”与包含 `code`、`purpose`、`expiresAt` 的单行文本。
- 模板变量契约固定为 `code`、`purpose`、`expiresAt`；HTML 变量会先转义再经过通知模块 sanitizer。
- 通知模块已经允许邮件所需的 `<style>`、内联 CSS、响应式 media query、表格布局与展示属性，同时继续拦截可执行 HTML。
- Safe House 现有文档页面采用浅灰背景、白色卡片、深色正文和青绿色强调色 `#08736a`。

## Requirements

- 为 `account.email.verify` 提供完整 HTML 内容，采用已确认的 Safe House 青绿色克制事务邮件风格，突出六位验证码，并清晰展示用途和过期时间。
- 使用适合常见邮件客户端的表格布局与内联关键样式；窄屏下保持可读，不依赖 JavaScript、外部样式表或远程图片。
- 保持 `code`、`purpose`、`expiresAt` 变量契约以及纯文本降级内容可用。
- 文案提示用户若未发起操作可忽略邮件，并避免要求回复邮件或点击未知链接。
- 通过新增后续迁移更新既有数据库中的固定模板记录，不篡改已发布迁移的历史行为；只为仍未配置 HTML 的默认模板补齐内容，保留管理员已有自定义。
- 增加聚焦测试，证明迁移包含 HTML、变量完整且关键邮件样式能通过现有渲染器保留。

## Acceptance Criteria

- [x] 邮件以品牌化卡片呈现，验证码是首要视觉信息，用途、有效期和安全提示层级清晰。
- [x] 320px 左右的窄屏与桌面宽度下内容均无需横向滚动，验证码不会难以辨认或断裂。
- [x] Gmail、Apple Mail、Outlook 常用渲染能力缺失时仍能依靠表格和内联样式保持基本结构。
- [x] 不引入外部字体、远程图片、脚本、表单或可执行内容。
- [x] 新迁移只更新 `account.email.verify` 的空 HTML 字段；管理员已有 HTML 不会被覆盖，回滚也不会删除迁移后产生的自定义内容。
- [x] 现有通知模板安全测试、邮箱验证契约测试、lint 与构建通过。

## Key Decisions

- 视觉采用浅灰背景、白色卡片、深色正文与 `#08736a` 青绿色强调色，不引入图片或额外品牌资产。
- 兼容性优先：核心结构使用展示型表格和内联样式，响应式 `<style>` 只作为增强。
- 本次只补充 HTML；主题、纯文本和变量契约保持不变。
- 新迁移对管理员自定义采取保守策略，仅填充 `html IS NULL` 的默认模板。

## Out of Scope

- 修改验证码生成、校验、限流、投递队列或 SMTP 配置。
- 新增 logo 图片、跳转按钮、邮件预览编辑器或通用模板设计系统。
- 为 `purpose` 或 ISO 时间新增服务端格式化变量；本次只优化既有 HTML 模板样式与文案层级。
