H OIDC 第三方接入指南

使用 OpenID Connect Authorization Code Flow + S256 PKCE 接入 H 登录中心。示例适用于有 Node.js 后端的 JavaScript / TypeScript 系统。

1. 配置字段

字段值或说明
OIDC_ISSUERhttps://h.exia.xyz/oidc
Discovery URLhttps://h.exia.xyz/oidc/.well-known/openid-configuration，由 OIDC 客户端自动访问。
OIDC_CLIENT_ID在 H 子应用管理中取得的应用 ID。
OIDC_REDIRECT_URI第三方系统自己的 HTTPS 回调地址，必须在 H 中登记并精确匹配。
SESSION_SECRET第三方系统自行生成，用于保护自己的 Session，不提交给 H。
OIDC_CLIENT_SECRET可选。默认 public client 不配置；仅 confidential client 在服务端兑换 Token 时使用。
https://sf.imouto.tech 是用户登录和授权确认页面。第三方系统不应将它配置为 Issuer、Token Endpoint 或 Redirect URI。

2. 登录流程

  1. 第三方后端生成一次性的 state、nonce 和 code_verifier，计算 S256 code_challenge。
  2. 浏览器跳转到 Discovery 返回的 authorization_endpoint，请求 openid profile email scope。
  3. 用户在 H 登录中心完成登录和授权确认。
  4. H 将浏览器重定向到已登记的 Redirect URI，并携带 code 和 state。
  5. 第三方后端校验 state，使用 code 和 code_verifier 调用 token_endpoint。
  6. OIDC 客户端验证 ID Token 的签名、iss、aud、有效期和 nonce。
  7. 第三方系统使用 ID Token 的 sub 关联用户，并建立自己的登录 Session。
授权码有效期 120 秒且只能使用一次。ID Token 和 Access Token 有效期 600 秒，不签发 Refresh Token。

3. TypeScript / JavaScript 示例

安装依赖

Terminal
npm install express express-session openid-client

最小服务端实现

以下为 public client 的 JavaScript 示例；TypeScript 可直接使用相同 API。

server.mjs
import express from 'express';
import session from 'express-session';
import * as oidc from 'openid-client';

const config = await oidc.discovery(
  new URL(process.env.OIDC_ISSUER),
  process.env.OIDC_CLIENT_ID,
  undefined,
  oidc.None(),
);

const app = express();
app.use(session({
  secret: process.env.SESSION_SECRET,
  resave: false,
  saveUninitialized: false,
}));

app.get('/auth/login', async (req, res) => {
  const verifier = oidc.randomPKCECodeVerifier();
  const state = oidc.randomState();
  const nonce = oidc.randomNonce();
  req.session.oidc = { verifier, state, nonce };

  const url = oidc.buildAuthorizationUrl(config, {
    redirect_uri: process.env.OIDC_REDIRECT_URI,
    scope: 'openid profile email',
    state,
    nonce,
    code_challenge: await oidc.calculatePKCECodeChallenge(verifier),
    code_challenge_method: 'S256',
  });
  res.redirect(url.href);
});

app.get('/auth/callback', async (req, res, next) => {
  try {
    const saved = req.session.oidc;
    if (!saved) return res.sendStatus(400);

    const callback = new URL(req.originalUrl, process.env.OIDC_REDIRECT_URI);
    const tokens = await oidc.authorizationCodeGrant(config, callback, {
      pkceCodeVerifier: saved.verifier,
      expectedState: saved.state,
      expectedNonce: saved.nonce,
    });
    delete req.session.oidc;
    req.session.userId = tokens.claims().sub;
    res.json({ sub: req.session.userId });
  } catch (error) {
    next(error);
  }
});

app.listen(3000);

4. 接入约束

  • 必须使用 response_type=code 和 code_challenge_method=S256。
  • scope 仅支持 openid profile email，其中 openid 必填。
  • 使用 sub 作为稳定用户标识，不要使用 email 作为主键。
  • Redirect URI 必须完整匹配，不能依赖前缀匹配或通配符。
  • public client 不传 Client Secret；confidential client 仅支持 client_secret_post。
  • 不要硬编码 Authorization、Token、UserInfo 或 JWKS 路径，以 Discovery 返回值为准。
  • 不要只解码 ID Token；必须使用 OIDC 客户端完成签名和 claims 校验。
